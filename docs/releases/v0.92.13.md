## The desktop app checks the shell its own herdr opens before it starts a run there

The desktop app starts a run by typing its command line into a new pane of herdr, and refuses to when that pane's
shell is not one it can type into (sh, bash, zsh, dash, ksh or fish). For a project on a machine it checked the
machine's herdr, where the run's agents are typed, but typed the run's own line into the herdr it reaches itself: a
local herdr whose panes start nu took a machine project's run, and the line was typed into nu. The app now checks the
shell of the panes it types the run's line into before it opens a workspace, and for a project on a machine checks
the machine's as well. A run of a local project is checked once, as before.
