## The engine reads the gate's quality.json

- **A quality round decides from `quality.json`.** Whether the gate passed, its failed conditions, the fingerprint of
  each failing finding and the failing tests now come from the build's `quality.json`, the gate release's report as
  data, rather than from parsing `quality.md`. The Builder and the Reviewer still read `quality.md`, with the
  orchestrator's own checks added, in the same words as before.
- **A stuck loop is judged on every failing finding.** `quality.md` lists at most 50 findings; `quality.json` lists
  them all, so two rounds that differ only past the 50th are no longer taken for the same failures again.
- **A report the engine cannot read stops the round.** A `quality.json` whose `schema_version` is not 1 stops the
  round with an error naming the version, and a `quality.md` whose GATE line is not its `quality.json`'s gate is
  rejected.
- **Older quality jobs still work.** A build that archived no `quality.json`, from a quality job whose `main` judges
  with a gate older than octoflow-gate 0.5.0, is read from `quality.md` as before. Runs saved by an earlier version
  resume unchanged.
