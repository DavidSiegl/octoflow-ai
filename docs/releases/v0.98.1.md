## The app's codex check sees keyring logins, and codex runs can log in with an API key

The desktop app's setup check of codex over ACP used to count codex as logged in only when `auth.json` existed, so a
login kept in the OS keyring failed it. The check now asks codex's agent, which reports the login from whichever store
holds it. A non-blank `CODEX_API_KEY` or `OPENAI_API_KEY` counts as a login too: a codex run's agent then logs in
with the key when a session needs a login, so `codex login` is no longer needed first. An agent that reports no login
within the probe's 30 seconds fails the check and says so.
