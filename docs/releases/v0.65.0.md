## The desktop app is the orchestrator itself

- **The app bundles no second program.** The desktop app's executable now has the orchestrator built in, where it
  carried a separate orchestrator binary beside it before. Its commands and flags, and the paths to it, are
  unchanged: the AppImage file itself, the `.deb`'s `/usr/bin/octoflow`, and
  `Octoflow.app/Contents/MacOS/octoflow`. For its window the app starts itself a second time, as `octoflow serve`,
  and stops that when the window closes. The plain binaries (`octoflow-linux-x86_64`, `octoflow-macos-arm64`) are
  released as before.
- **`ORCHESTRATOR_BIN` is no longer read.** The app cannot serve another orchestrator than its own; to try another
  build, run that build's `serve`, or build the app from its checkout.
- **An AppImage's window started from a directory since removed shows no runs.** It says that its server did not
  start, and the app prints `cannot start in <directory>: it is not a directory`, as the CLI does, where the
  window served the app's own directory before.
