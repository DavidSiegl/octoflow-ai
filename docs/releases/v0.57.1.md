## serve shows the desktop app nothing a symbolic link leads it to outside a run

- **serve no longer shows a file outside a run through a symbolic link.** A link an agent left in its run directory,
  or a run directory that was itself a link, let `/file` and the event stream show the desktop app any file the
  user can read, `~/.ssh/id_rsa` say. Now `/file` refuses with 403, and `/files` and the stream leave out, a file
  that, links resolved, is not inside its run directory, and every file of a run directory that is not inside the
  project's `.orchestrator/runs`. A link that stays inside the run directory is read and listed as before.
- **A run whose `state.json` leads out of its run directory is no run to serve.** `/runs` and the stream's `record`
  events leave it out, as they leave out a run without a `state.json`, and `/agent` answers 404 for it.
- The links are resolved on the project's host, over SSH too, with what `sh` has on Linux and macOS alike. The
  engine's own commands (`list`, `show`, a running run) still follow links as before.
