## Three edge cases of ACP runs: resumes past a finished role, a pending turn's usage, and herdr's refusals

Resuming an ACP run now checks only the harnesses of the roles the run can still start, so a role it has finished
whose harness cannot run under the new mode no longer blocks the resume. When an ACP run counts its tokens, starts a
role's agent again or ends its agents, a prompt still pending is given up to 10 seconds to be answered, then cancelled
and given as long again, so the usage its answer carries is recorded; an interrupted run still skips that wait. And
the desktop app says "cannot reach herdr" only when herdr could not be run or has no server running: a text or key
herdr refuses is reported in herdr's own words.
