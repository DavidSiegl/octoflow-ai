## opencode takes its model, and writes a worktree run's handoff files without asking

- **An opencode role given a model starts again.** The engine passed opencode `--model`, which opencode 2.0.24's
  interactive interface does not take: it printed its help and exited, so the role never started. opencode now gets
  its model as `model` in an `OPENCODE_CONFIG_CONTENT` that its pane's shell exports just before starting it, and it
  starts with `--standalone`, as opencode's shared background service would ignore the variable.
- **A `--worktree` run's opencode agent no longer stops to ask before writing its handoff file.** The handoff files
  are in the project's run directory, outside the worktree the agent works in, and opencode asks before writing
  outside its working directory, so herdr showed it blocked on each turn. The same config now allows that directory
  (`permission.external_directory`), as claude, codex and gemini are given it by a flag. pi asks before no write,
  and needs nothing.
- The pane's shell must take `export NAME='value'`, as sh, bash, zsh and fish do. The engine types that line only
  into a shell at its prompt, and fails the start, saying so, when the shell does not run it.
