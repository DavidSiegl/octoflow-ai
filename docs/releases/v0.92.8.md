## One broken state.json no longer stops every command that lists the runs

A run's state.json that was not JSON, not UTF-8 text, or not a JSON object with a run id made every command that lists
the runs fail, without saying which file it was: `list`, `refresh`, `close RUN` and `close --all` did nothing, and the
desktop app could not show the project's runs. Such a run is now listed as an unreadable run, as a state.json of a
format this release does not read already was, and since its file names no run, it is named by its directory. Its
problem names the file and what is wrong with it, and says to fix the file or remove the run's directory. The other
runs list, refresh and close as before, the desktop app shows the broken one in its run list with that problem, and
since no release of octoflow writes such a file, it never counts as a running run. octoflow does not repair or
remove the file itself.
