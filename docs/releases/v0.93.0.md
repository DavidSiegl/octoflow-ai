## The desktop app's new run asks for a permission mode

The desktop app's "New run…" form has a permission mode for every role: `default`, `acceptEdits`, `plan` or
`bypassPermissions`, by Claude Code's names, as `--permission-mode` takes them on the CLI. It starts at `default`, so
every harness asks before it runs a command unless you pick another; beside `plan` the form says agents write nothing
under it, so the run stops at its first handoff. Runs the app started before passed no mode, so each harness started
in its own configured default.

serve's `POST /run` takes the mode as `permission_mode` and refuses any other value with 400, and `GET /workflows`
offers the four as `permission_modes`. A body without the field starts the run without `--permission-mode`, as
before.
