## The schema-version error names the pin

When a quality round's `quality.json` has a `schema_version` this engine does not read, the error no longer tells you
to change a Jenkins quality job, which octoflow has not used since 0.71.0. It now says the report came from the
release that judged the run: the one the run's base pins in `ci/gate.pin`, or the one built into octoflow when the
base pins none. To fix it, pin a release in the base's `ci/gate.pin` that writes the version this engine reads, or
use an octoflow that reads the other.
