## drain takes up a conflict that `refresh` cleared before it

- **A spec held back only by its pull request's conflict goes to review once `refresh` clears it.** A drain leaves a
  spec `ready-for-human` when its run opens the pull request over conflicts with the base. Until now, a later drain
  moved it to `in-review` only if that drain's own refresh cleared the conflict; one cleared by `refresh` run by hand
  first left the spec `ready-for-human`, and no drain marked it `done` once merged. Now `refresh` records in the run's
  `state.json` (`conflict_cleared`) that it cleared the conflict of an open pull request, and the next drain takes it
  up once: it moves the spec to `in-review` if its run approved or finished and the pull request is still open, or to
  `done` if it has merged, and removes the record once the spec's header is written. If `gh` cannot tell it the pull
  request's state, drain says so, leaves the spec and tries again next time, rather than failing. A spec you set back
  to `ready-for-human` after that, or set so for any other reason, is left alone. Earlier releases keep the new field
  through a save and ignore it.
