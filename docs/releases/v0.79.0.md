## Create, edit and delete workflows in the desktop app

- **"Workflows…"** in the top bar lists every workflow `orchestrator workflows` lists, with its file and
  description. A workflow whose file does not load shows its path and error, and offers only Delete: fix it by
  hand.
- **New, Duplicate and Edit** open an editor with a field for every key of a workflow file: the description, the
  diff budget and the proof command, the roles as a table (key, label, agent, model), and the steps as a list to
  add to, remove from and reorder, each with its id, role, file, prompts, `loop_to` and flags. Each step's prompts
  sit beside the placeholders they may use. A built-in workflow opens read-only, with Duplicate… in place of Save.
- **The orchestrator checks the workflow as `run` would** a moment after each change, and Save stays off while it
  names a problem, such as an unknown `loop_to` or placeholder.
- **Saving writes the canonical form** to `workflows/NAME.toml`: no comments, no `use` lines, a `use` step's text
  from the built-in prompts. Before it rewrites a file written by hand, the editor asks. A save is refused when the
  file changed since the editor opened it, or a new workflow's name is taken. Reload reads the file again.
- **Delete** asks first, naming the file. A run already started keeps its own copy of the workflow.
- Closing the editor with unsaved changes asks Save, Discard or Cancel.
