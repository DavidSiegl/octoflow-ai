## A failing test's line in a build-failed report says what failed

- **A quality round of a build that ended before its gate** lists each failing test with its message, not only the
  line that says where: for a Rust panic, the line after `thread '…' panicked at …:` too, and any line naming
  `OCTOFLOW_TEST_SEED`, so that the Builder can run the failing case again with the seed Jenkins drew.

## A snapshot's copy of git's index stays private and leaves nothing behind

- **The engine's working-tree snapshots** stage into a copy of git's index kept in a temporary directory of its own,
  which only its owner can enter and which is removed whole when the snapshot ends, an `index.lock` a killed git left
  there included.

## Setting up the quality gate keeps a file made meanwhile, and is quicker over SSH

- **`doctor --setup-gate` and the desktop app's "Set up the quality gate"** never replace a `gate.toml` or
  `ci/gate.pin` that appears while they run, as one from a second click would: each file is linked into place only
  where nothing is, and reported as kept otherwise. The setup takes two commands on the agents' machine, where it
  took up to thirteen, each a round trip over SSH.

## doctor's local quality gate check says why it needs gitleaks in doctor's words

- **`doctor`'s `local quality gate` check**, on a machine whose gitleaks is missing or lacks `gitleaks git`, says what
  is wrong with it and that the gate scans each snapshot for secrets with it, with the install instructions as its
  fix, where it said "this run pushes" and gave the install instructions twice.

## opencode gets no write grant that would reach past the run directory

- **An opencode agent whose run directory's path holds `*`, `?` or `\`** starts without the grant to write there,
  which opencode would read as a pattern also covering other directories. It asks in its pane before each such write
  instead, as before 0.67.1.

## doctor tells a missing tool on a herdr machine whatever its login shell

- **`doctor --machine`** looks git, gh and herdr up on the machine's PATH before running them, so a missing one is
  reported as not on PATH where the login shell is csh or tcsh, and not as a failed `--version` or login; and a tool
  that is there but exits 127 itself, such as a shim whose target is gone, is reported as failing, not as missing.
