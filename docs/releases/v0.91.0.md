## A project follows octoflow's gate release unless it pins one

`octoflow doctor --setup-gate` and the desktop app's "Set up the quality gate" now write only the starter
`gate.toml`. A project without `ci/gate.pin` is judged by the octoflow-gate release built into the octoflow that runs
it, so updating octoflow updates the gate. To hold a project at one release, pass `--pin-gate <version>` (0.7.0 or
later) with `--setup-gate`: doctor writes `ci/gate.pin` for that release, with a comment saying that deleting the
file makes the project follow octoflow's release again. `--pin-gate` without `--setup-gate` is a usage error.

doctor's local quality gate check now says which release judges the project. Projects set up earlier carry the pin
setup-gate used to write; when it is older than the built-in release, the check says so and that deleting
`ci/gate.pin` follows the built-in one. A pin newer than the built-in release is a warning, since this octoflow may
not read that release's report. Nothing deletes a pin for you.
