## A worktree run with nothing to publish no longer leaves an empty worktree behind

A `--worktree` run that ended approved without changing anything git tracks kept its worktree, detached, even when
nothing was in it, and no command removed it later. Such a run now removes its worktree when it holds no file but the
engine's own (its `.octoflow-ai/.gitignore` and proof copies). A worktree that holds any other file, if only an
ignored one, is still kept, detached, as before; so is one git will not remove, such as a locked one or one with a
submodule, and the run logs git's reason rather than failing.
