## What a proof writes in the project stays out of the commit

- **A proof leaves the working tree as it found it.** A proof runs in the tree the Builder is changing, so that the
  project's test configuration applies, and anything it wrote there besides its own copy, such as a coverage file, a
  test's output or the `__pycache__` of a module it imports in a project that does not ignore those, stayed and was
  committed with the change; so was an edit it made to a project file. Now the tree is snapshotted before each proof
  and every file that differs afterwards is put back: a file or directory the proof added is deleted, one it changed
  or deleted is restored. This holds when the proof fails, errors or is stopped with Ctrl-C too. Files the
  project's own rules ignore are left alone, since they are never committed, except in a directory the proof made a
  repository of (below). Those rules are the `.gitignore` files git does not ignore, `.git/info/exclude` and
  `core.excludesFile`.
- **A directory the proof made a repository of loses everything those rules do not ignore**, its `.git` and every
  repository nested in it included. A repository in it that those rules ignore, or one that was there before the
  proof, stays whole with its history. Every `.gitignore` in it that was not in the tree before the proof is deleted
  too, with the files only it ignored: one that ignores itself, as pytest, mypy and ruff write theirs with `*`, so
  such a cache directory goes whole, and one of yours that the project's rules ignore.
- **In a run without a worktree, edits you make while a proof runs are put back too.** Such a run works in your
  checkout, and everything that changed there during a proof is undone, whoever changed it: a file you save is
  overwritten, and a new file you create, unless git ignores it, is deleted. Leave the checkout alone while proofs
  run, or use `--worktree`.
- **A proof whose writes cannot be undone did not run cleanly.** Its outcome says so, with git's or `rm`'s error, and
  it does not count as demonstrating its finding; the run goes on.
- **Nothing is put back outside a git repository**, or where git cannot snapshot the tree, as with a nested
  repository that has no commit; the latter is logged, and the proof runs as before.
