## The secret scan's limit on binary files is documented

Nothing the orchestrator or the desktop app does changes. A file git takes for binary (a NUL in its first 8000 bytes)
was never read by the pre-push secret scan, and still is not: the README and the engine's comment on the scan now say
so, and that a path rule in the base's `.gitleaks.toml` is what catches a secret in one, a `.p12` keystore say.
