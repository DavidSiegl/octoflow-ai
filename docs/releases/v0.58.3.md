## The secret scan's limit on binary files is documented

Nothing the orchestrator or the desktop app does changes. A file git takes for binary (a NUL in its first 8000 bytes,
or over 512 MiB) was never read by the pre-push secret scan, and still is not: the README and the engine's comment on
the scan now say so. No rule in `.gitleaks.toml` reaches such a file, not even a path rule, so a secret in one, a
`.p12` keystore say, is pushed unreported. Keep such files out of the repository.
