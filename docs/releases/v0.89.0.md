## A project's own directory is `.octoflow-ai/`

What the engine keeps in a project, its runs, their worktrees and state, now lives in `<project>/.octoflow-ai/`
instead of `<project>/.orchestrator/`, after the product, as the configuration directory has been since 0.82.0.

- **The move is automatic, once.** The first command, or `serve`, that finds an older engine's `.orchestrator/`,
  and no `.octoflow-ai/`, renames it, registers each worktree kept under it with git at its new path, saves its run
  with that path, and says on standard error what it moved. `list`, `show`, `prune`, `forget`, `metrics` and the
  desktop app then find the runs as before.
- **Close your runs first.** The move waits until every run under `.orchestrator/` is closed: until then, each
  command on the project refuses, moves nothing, and names the open runs, `close` and the desktop app included.
  Finish or stop each with the engine you have, `close` it, then upgrade. An open run's agents and saved state name paths under `.orchestrator/`, so moving
  it would break it.
- **A dry run moves nothing.** `close --dry-run`, `forget --dry-run`, `prune --dry-run` and `drain --dry-run`
  refuse while the move is due, saying the first other command will make it.
- **A worktree the move cannot carry over is named.** The move still happens; the message says what to do by
  hand: a `git worktree repair` to run, or a run's saved `worktree` to set.
- **An older engine no longer sees the runs.** After the move, an engine from before 0.89.0 finds nothing in
  `.orchestrator/`. Don't switch back and forth between versions on one project.
- **Another tool's `.orchestrator/` stays.** A directory by that name without the engine's `runs/` in it is left
  alone.

The directory still keeps itself out of git through its own `.gitignore`, which moves with it.
