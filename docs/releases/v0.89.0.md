## A project's own directory is `.octoflow-ai/`

What the engine keeps in a project, its runs, their worktrees and state, now lives in `<project>/.octoflow-ai/`
instead of `<project>/.orchestrator/`, after the product, as the configuration directory has been since 0.82.0.

- **The move is automatic, once.** The first command, or `serve`, that finds `.orchestrator/` and no `.octoflow-ai/`
  renames it, re-registers each worktree under it with git at its new path, rewrites each run's saved worktree path,
  and says on standard error what it moved. Nothing else is needed; `list`, `show`, `resume`, `close` and the desktop
  app find the runs as before.
- **It waits for live runs.** While a run under `.orchestrator/` is still `running`, driven by an older engine, the
  command refuses, moves nothing, and names the run. Let it end, or stop it, then start again.
- **An older engine no longer sees the runs.** After the move, an engine from before 0.89.0 looks in
  `.orchestrator/` and finds nothing. Don't switch back and forth between versions on one project.
- **An interrupted move is not repaired.** If the move fails or is interrupted after the rename, git's records of the
  worktrees, or the saved worktree paths, can still point at `.orchestrator/`. Run `git worktree repair` in the
  project for the one, and fix `worktree` in the run's `state.json` for the other.

The directory still keeps itself out of git through its own `.gitignore`, which moves with it.
