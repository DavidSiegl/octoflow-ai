## A project's own directory is `.octoflow-ai/`

What the engine keeps in a project, its runs, their worktrees and state, now lives in `<project>/.octoflow-ai/`
instead of `<project>/.orchestrator/`, after the product, as the configuration directory has been since 0.82.0.

- **The move is automatic, once.** The first command, or `serve`, that finds `.orchestrator/` holding runs, and no
  `.octoflow-ai/`, renames it, registers each worktree kept under it with git at its new path, and says on standard
  error what it moved. `list`, `show`, `forget` and the desktop app then find the runs as before.
- **Close your runs first.** The move waits until every run under `.orchestrator/` is closed: until then, each
  command on the project refuses, moves nothing, and names the open runs. Finish or stop each with the engine you
  have, `close` it, then upgrade. An open run's agents and saved state name paths under `.orchestrator/`, so moving
  it would break it.
- **A dry run moves nothing.** `close --dry-run`, `forget --dry-run`, `prune --dry-run` and `drain --dry-run`
  refuse while the move is due, saying the first other command will make it.
- **A worktree git cannot register again is named.** The move still happens; run the `git worktree repair` the
  message gives.
- **An older engine no longer sees the runs.** After the move, an engine from before 0.89.0 finds nothing in
  `.orchestrator/`. Don't switch back and forth between versions on one project.
- **Another tool's `.orchestrator/` stays.** A directory by that name that holds no runs of the engine is left alone.

The directory still keeps itself out of git through its own `.gitignore`, which moves with it.
