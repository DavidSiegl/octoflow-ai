## octoflow has no Python of its own

- **The version lives in `engine/Cargo.toml`.** The release's version was `pyproject.toml`'s, which the engine's had
  to match; now it is the engine's own, and the desktop app's version, the release's tag and Jenkins's check that a
  pull request raises it all read it from there (`ci/release-version.sh`). Nothing changes for a run.
- **No Python tests.** The tests of the `ci/` scripts are Rust tests now, run with the rest by `cargo test`.
  `pyproject.toml`, `uv.lock` and `.python-version` stay only for the quality gate's toolchain, until the gate needs
  no Python.
