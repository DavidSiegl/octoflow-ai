## Locked files and the change's checks see the whole repository under `diff.relative`

- **A run whose directory is a subdirectory of the repository no longer loses files to the user's `diff.relative`.**
  With `diff.relative = true` in the user's git config, every `git diff` the engine ran from a subdirectory listed
  only the files under it. A step's locked files then left out every file elsewhere, so a later step's edit to one of
  them was neither reported nor restored; the quality checks judged only the part of the change under that
  subdirectory; and a merge from origin whose conflicts all lay elsewhere was reported as a merge that failed without
  a conflict. The engine's diffs now always cover, and name paths from, the repository's top level.
- **The diff a step is shown of the locked files it changed names a path that is not ASCII as it is**, rather than
  in git's octal escapes, as the quality checks' diffs already did.
