## The Linux AppImage's CLI stops when its runtime does, without FUSE

- **An AppImage run without FUSE stops its orchestrator when it is stopped.** On a machine without FUSE
  (`APPIMAGE_EXTRACT_AND_RUN`), the process a caller starts is the AppImage's runtime, which passed on no signal: a
  `kill`, a `timeout` or a systemd stop ended the runtime and left the orchestrator, and the agents it ran, going on
  unsupervised. Now the orchestrator gets SIGTERM when the runtime dies, whatever stopped it, and ends as it does at
  any SIGTERM. Ctrl-C still stops it; without FUSE the orchestrator, which gets the SIGINT too, now also gets the
  SIGTERM once the runtime has died of it, and may end with status 143 rather than 130, a status only the runtime
  sees. The AppImage mounted through FUSE behaves as before.
