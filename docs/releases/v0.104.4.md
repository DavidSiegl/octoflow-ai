## A failed ACP run records the usage of the prompts its agents had pending

When an ACP run stopped on a failure, as opposed to a Ctrl-C or the app's stop, it killed its agents with their
prompts still pending. Those prompts' usage never reached `acp-usage.jsonl`, so their turns could count "unknown"
tokens on a later resume. A failed run now does what an interrupted one does: it cancels what its agents have pending
at once and gives them up to 2 seconds to answer with their usage before it is released. A run another orchestrator
took over still records nothing more, since the run and its files now belong to that orchestrator.
