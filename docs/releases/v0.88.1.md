## A pane shell no run can use is named, not run into

- **`doctor` checks the shell herdr's panes start**: `[terminal] default_shell` in herdr's `config.toml`, else
  `$SHELL`, where the agents run. A shell other than sh, bash, zsh, dash, ksh or fish, such as nushell, xonsh or
  PowerShell, fails the check, and the desktop app's setup dialog shows it.
- **The desktop app refuses to start a run in such a shell**, naming it, before it opens a workspace. Before, the
  run's typed command failed in the pane, and the app showed the shell's error or waited for a run that never
  started.

## A read of origin that hangs is tried again

- **A fetch or `ls-remote` that stalls ends within about a minute and a half** and is tried again, as an outage of
  origin is: over HTTPS when under 1000 bytes a second arrive for 60 s, over SSH when no connection is made in 30 s
  or the server stays silent through four keep-alives 15 s apart. Before, such a read ran until the engine killed it
  after 300 s, and the run stopped there.
- **What your own configuration sets is kept**: git's `http.lowSpeedLimit` and `http.lowSpeedTime`, ssh's
  `ConnectTimeout` and `ServerAliveInterval` for origin's host, and any ssh command of your own (`GIT_SSH_COMMAND`,
  `GIT_SSH`, `core.sshCommand`, `ssh.variant`), which runs without either limit.
- A read the engine still kills at 300 s is tried again too, and says `<git command>: origin did not answer within 300
  seconds`. Pushes, deletions on origin and local git commands that run out of time are not tried again.

## One answer for a harness the orchestrator does not take

- **`--agent`, `--role-agent` and serve's run body** (`agent` and each of `role_agents`) refuse a kind that is not a
  harness with the words a saved run or workflow file gets: `gemini` is answered that agy replaced it, and any other
  unknown kind with the list of kinds there are. Until now each gave its own message, and `gemini` got only the list.
- serve's `role_agents` with a value that is not a string, or an empty one, is refused as "an object of role to a
  string that is not empty"; a string naming no harness gets the refusal above.

## The Reviewer judges a loosened lint configuration

- **The Reviewer's note on the quality file** (`QUALITY_PASSED_NOTE`, `QUALITY_UNRESOLVED_NOTE`,
  `QUALITY_STUCK_NOTE`) now ends by telling it to judge each edit to lint or clippy configuration that the file lists
  under Build configuration as a finding: whether the spec justifies the loosening, and to request changes when it
  only hides a finding. The gate's clippy reads the change's own configuration, so such an edit passes the gate.
- A prompt file that overrides one of these notes keeps its own text.

## The desktop app names the verdict step that sent a run back

- **A finished run judged by several verdict steps** shows, in the app's run overview, which step's verdict ended it,
  as `list` does: "CHANGES_REQUESTED by accept" rather than "CHANGES_REQUESTED". An approved run, a run of a workflow
  with one verdict step, and a run saved before 0.58.0 show the bare verdict, as before.

## A dialog keeps the keyboard and the mouse to itself

- **Nothing behind the run form or the setup dialog can be reached while it is open**: Tab, clicks and keys stay in
  the dialog. Before, the project bar under the run form could open another project while a run was starting, and
  the started run was then never selected, or its failure never shown.

## The desktop shell's tests move to a file of their own

- **Nothing a user sees changes with this move**: the desktop shell's tests moved out of `ui/src-tauri/src/lib.rs`
  into `ui/src-tauri/src/tests.rs`, so a later change to them alone needs no release.
