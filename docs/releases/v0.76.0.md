## Clean up runs from the desktop app

- **"Clean up runs…"** above the overview shows what `orchestrator close --all` would do to each of the project's
  runs, by its task: the workspace, refs, worktree and branch it would close, delete or keep, the uncommitted
  changes that would go with a failed run's worktree, and why a run still running is skipped. Runs closed before
  are counted, not listed. Close closes the runs it showed, and only while each would still close as shown: a run
  that changed since, such as a worktree with a new change, is skipped. It then shows how each went, a failure with
  its run and any changes that went with its worktree; the overview shows the runs closed, as `list` does. With
  nothing to close the dialog says so and offers no Close, and it says when runs could not be looked at.
- **`serve` answers `POST /close?cwd=DIR[&machine=M]`**: the body `{"dry_run": true}` sweeps as `close --all
  --dry-run` does; `{"close": [{"run", "detail", "discarded"}]}`, the dry run's `closed` runs, closes those and no
  other, each only while it would still close as the dry run said. It answers `{"runs": [{"run", "outcome",
  "detail", "discarded"}]}`, `outcome` being `closed`, `already closed`, `skipped` or `failed`. It sweeps in serve's
  own process.
- **The overview shows a closed run as closed**, as `list` does: what it was, then `closed: <what closing did>`.
