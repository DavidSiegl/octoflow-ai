## Clean up runs from the desktop app

- **"Clean up runs…"** above the overview shows what `orchestrator close --all` would do to each of the project's
  runs, by its task: the workspace, refs, worktree and branch it would close, delete or keep, the uncommitted
  changes that would go with a failed run's worktree, and why a run still running is skipped. Runs closed before
  are counted, not listed. Close closes them and shows how each went, a failure with its run; the overview follows
  through its event stream. With nothing to close the dialog says so and offers no Close.
- **`serve` answers `POST /close?cwd=DIR[&machine=M]`**, with the body `{"dry_run": true}` or `{"dry_run": false}`:
  `{"runs": [{"run", "outcome", "detail", "discarded"}]}`, one per run the sweep looked at, `outcome` being
  `closed`, `already closed`, `skipped` or `failed`. It sweeps as `close --all` does, in serve's own process.
