## A role's agent starts again after a crash cut its journal mid-line

An ACP run keeps each role's journal, `<role>.events.jsonl`. When the orchestrator died while writing a line, as in a
crash or a kill, and the cut fell inside a multibyte character, the role's next agent failed to start on resume with
"cannot read …". The journal is now read past such a line. The cut line is also ended before anything is appended:
before, the resumed session's first line ran on from it, so neither line read, and a permission wait open at the
crash counted until the next session. The same holds for a line a failed write cut short while the run goes on, as
on a full disk.

The app shows such a journal too: serve now reads a run's files with each byte that is not UTF-8 replaced, where it
refused them before, so the resumed agent's permission requests reach the app. A journal whose first line a crash
cut is begun again, where serve then reported it as from another version of octoflow.
