## A run in your checkout says what a proof's clean-up put back

A run without a worktree works in your checkout, and after each proof it puts back every file that changed while the
proof ran, whoever changed it. A file you saved there during a proof was undone without a word.

- **Each file put back is named in the run's log**, also when putting them back fails partway, with a command that
  makes them again what they were when the proof ended: `rm` for files that were gone then, and `git restore
  --source=<tree> -- <files>`. A proof that changed a `.gitignore` gets two such lines. The tree stays in git for two
  weeks under git's default `gc.pruneExpire`, and a nested repository the clean-up removed comes back empty. Your save
  is still undone, since nothing tells it from the proof's own writes; the line tells you which files to check.
- **A run in its own worktree logs nothing new**: no one edits that tree but the run.
