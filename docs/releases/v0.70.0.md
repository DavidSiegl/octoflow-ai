## The quality gate is octoflow-gate 0.10.0

A base without `ci/gate.pin` is judged by octoflow-gate 0.10.0, not 0.7.0, and `orchestrator doctor --setup-gate`
and the desktop app's "Set up the quality gate" write a pin naming 0.10.0. A base that pins a release judges by that
release, as before. Three gate releases lie between the two, and each can fail a change 0.7.0 passed;
[octoflow-gate's docs](https://github.com/DavidSiegl/octoflow-gate/blob/v0.10.0/docs/quality-gate.md) say how each
check reads a project.

- **Go (0.8.0, 0.9.0)**: the `.go` files of a Go module are read for test integrity, cognitive complexity and vague
  names; golangci-lint lints them, its findings on added lines failing the gate; and gremlins mutation-tests the Go
  functions a change edits. golangci-lint must be on `PATH` where the gate runs: a project that tracks Go files and
  lacks it fails every quality round naming it, until it installs it or `gate.toml` sets
  `[linters] golangci-lint = []`. A Go project's starter `gate.toml` says so.
- **Dependency cycles (0.10.0)**: a change that closes a new import cycle between a Python or Rust project's modules
  fails the gate; `gate.toml`'s `[dependency-cycles] exempt` names the files that take part in no cycle.
- **The quality file and quality.json are read as 0.7.0's were**: the schema is still version 1, and the release's
  golden reports are byte for byte 0.7.0's.

This repository is judged by 0.10.0 too: `ci/gate.pin` names it.
