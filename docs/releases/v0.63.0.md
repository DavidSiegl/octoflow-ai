## The quality gate without Jenkins

- **`--quality-gate local`.** `run`, `drain` and `resume` can have the quality gate judge each Builder turn on the
  project's own machine instead of a Jenkins job: the orchestrator fetches the octoflow-gate release the run's base
  pins in `ci/gate.pin`, checks it against the pin's sha256 each time it is used, caches it in
  `~/.cache/octoflow/gate/`, and runs it, as a job of its own, on a checkout of the change by the base's `gate.toml` and
  `pyproject.toml`. It needs `python3` 3.11 or later, curl, tar, ps, sha256sum or shasum and the project's test tools
  and linters on `PATH`, and no Jenkins, credentials or `origin`; nothing is pushed. The gate runs the project's tests
  as you, with no sandbox. docs/quality-gate.md, "The local gate", has the details.
- **A top-level Jenkins job named `local` is now written `/local`.** `local` names the local gate. A run saved by
  an earlier release with a build of such a job in flight is not resumed: finish it with that release, or close it.
- **The tests a gate run outside Jenkins measures are Jenkins's.** `gate.toml`'s test command is
  `ci/rust-tests.sh`, which the Jenkinsfile's Test stage runs too, so the e2e scenarios count to the engine's
  coverage there as well.
