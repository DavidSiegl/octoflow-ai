## The quality gate without Jenkins

- **`--quality-gate local`.** `run`, `drain` and `resume` can have the quality gate judge each Builder turn on the
  project's own machine instead of a Jenkins job: the orchestrator fetches the octoflow-gate release the run's base
  pins in `ci/gate.pin`, checks it against the pin's sha256, caches it in `~/.cache/octoflow/gate/<version>`, and
  runs it in the run's worktree by the base's `gate.toml` and `pyproject.toml`. It needs `python3`, curl, sha256sum,
  tar and the project's test tools and linters on `PATH`, and no Jenkins, credentials or `origin`; nothing is pushed.
  The gate runs the project's tests as you, with no sandbox. A top-level Jenkins job named `local` is now written
  `/local`. docs/quality-gate.md, "The local gate", has the details.
- **The tests a gate run outside Jenkins measures are Jenkins's.** `gate.toml`'s test command is
  `ci/rust-tests.sh`, which the Jenkinsfile's Test stage runs too, so the e2e scenarios count to the engine's
  coverage there as well.
