## A snapshot holds a file changed within a second

- **A file rewritten right after git staged it is no longer taken as unchanged.** The engine reads the working tree
  through a copy of git's index. The copy was dated now, which switched off git's own check of a file whose size and
  times are the index's (https://git-scm.com/docs/racy-git): a tracked file rewritten at the same size, within the
  second git last staged or checked it out, went into the snapshot as it was before. So a change's snapshot could
  miss such an edit, a locked file changed that way could pass as untouched, and putting the tree back after a
  proof could leave such a file as the proof wrote it, with a rewritten `.gitignore` then deleting a file it had
  ignored before. The copy keeps the index's time now.
