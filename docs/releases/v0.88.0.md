## Two workflow shapes that judged a round wrongly are refused

A custom workflow file that loaded under 0.87.2 can be refused when a run or `octoflow workflows` loads it. The
built-in workflows and the files in `examples/workflows/` load as before.

- **A verdict step whose loop edits nothing**: a `loop_to` that goes back to a step from which no step up to the
  verdict step has `edits = true` — another verdict step, say — is refused with "step accept loops back to review, but
  no step in that loop edits". Such a round judged the same change again, and no step answered the findings.
- **A step between two verdict steps that is not one**: only verdict steps may come between the first and the last.
  A non-editing step there is now refused too, with "step notes runs between verdict steps review and accept, so a
  round that review sends back would skip it"; its next turn was told of rounds it never ran. An editing step there
  was refused already, and its message is unchanged.

To fix a refused workflow, point the `loop_to` at the editing step (the Builder's), and move a step between verdict
steps before the first of them or after the last.

## The proofs note names no role

- **The note a step gets when proofs fail against its change** says "Findings were backed with tests" rather than
  "The Reviewer backed findings with tests": in a custom workflow the step that wrote the proofs may be of another
  role. The rest of the note is unchanged.

## A finished run's late files reach the desktop app too

- **summary.md and metrics.json show up even when the engine writes them slowly.** After a run finishes, serve's
  event stream lists its files on every poll until its state.json is a minute old. Before, the stream stopped after
  two polls, one or five seconds apart, so a summary written later than that, as it can be on a `--machine`'s project,
  showed only when the run's record next changed.

## A file removed while it is read is missing, not a failure

- **serve's `/file` answers "missing"**, as does its read of an agent's console for a run being pruned, when a run
  file is removed between the engine finding it and reading it, such as the secret scan's `leaks-publish.json`, instead
  of reporting a failure. Every other read of a file that goes away meanwhile reads it as not there yet, as it does a
  file never written.

## The desktop app's window has a minimum width

- **The window cannot be made narrower than 660 px**: below that the project bar's "Check setup…" button wrapped onto
  two lines and ran past the window's right edge.

## The npm notices ship every NOTICE file

- **A package's NOTICE files ship with its license**: `octoflow-desktop-npm-licenses.html` appends the `NOTICE*` files
  of every npm package the desktop app bundles, as Apache-2.0 §4(d) asks, not only Vite's and Rolldown's.
- **A build tool's third-party licenses are found under any name**: `THIRD_PARTY_LICENSES`, `ThirdPartyNotices.txt`
  and `LICENSE-THIRD-PARTY` ship with Vite's or Rolldown's notice like `THIRD-PARTY-LICENSE`, and the last no longer
  fails the build by passing for the package's own license.

## Stopping the desktop build stops its smoke test's serve

- **`packaging/build-desktop.sh` stops the AppImage's `serve`** when it is stopped during its smoke test, by a
  SIGINT, SIGHUP or SIGTERM sent to the script, before removing the directory serve runs in. Until now serve and the
  engine it runs kept running there, the directory gone. A Ctrl-C at a terminal, which reaches the whole process
  group, stopped them already, as does a Jenkins abort. Releases themselves are unchanged.
