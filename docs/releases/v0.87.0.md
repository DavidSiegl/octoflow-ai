## A peer-review workflow, built in

- **`--workflow peer-review` is for research written up and refereed**: a question answered with data, experiments,
  benchmarks or literature. An Editor agrees the question with you: hypotheses and what would refute them, the data
  and sources allowed, the methods, the manuscript's form and path, and what a publishable answer must show. An
  Author does the work in the project, with scripts, fixed seeds, a manuscript and one command that reproduces every
  figure and number. A Methods Referee reproduces it from a fresh copy and judges the design and statistics; a
  Domain Referee checks the claims, the related work and that each cited source exists and says what is claimed.
  The Editor decides from the two reports: accept, or send the work back with the points to address, and the next
  round runs both referees again on the Author's point-by-point response.

  The referees report one after the other and give no verdict; the Editor's decision is the round's verdict, and
  the Editor also weighs the quality gate's unresolved findings, which neither referee hears. Each referee is told
  not to read the other's reports, but nothing hides them, and from round 2 on the Author's response and the
  Editor's decision quote both. `--role-model methods=...` and `domain=...` set the referees' models. `octoflow workflows
  peer-review` prints the workflow as a file to start a variant of your own from.

- **A workflow file named `peer-review.toml` no longer loads.** As with `design` in 0.86.0, a file cannot take a
  built-in workflow's name. Rename yours (say `my-peer-review.toml`) to keep it, and run it as
  `--workflow my-peer-review`.
