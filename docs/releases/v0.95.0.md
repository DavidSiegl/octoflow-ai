## Tab completion

`octoflow` completes its own command line in bash, zsh and fish: subcommands, flags, `--workflow` names (your own
workflow files included) and, after `resume`, `show`, `close`, `forget` and `refresh`, the runs of the project, newest
first, by their six-character key (the full id where two runs share a key), with each run's phase and task in zsh
and fish. The shell asks `octoflow` on each Tab, so new runs and workflows show up without regenerating anything. Runs
are read from `--cwd`'s project, else the current directory's, and only on this computer: a line with `--machine` is
offered none. Turn it on with the line for your shell's startup file, as README's "Tab completion" gives it, e.g.
`source <(OCTOFLOW_COMPLETE=bash octoflow)`. The desktop app's binary, as the `.deb` installs it, completes too; the
AppImage is not supported.
