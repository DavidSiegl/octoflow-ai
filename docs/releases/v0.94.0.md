## The desktop app runs its agents over ACP and no longer needs herdr

Every run the desktop app starts now drives its agents over the [Agent Client Protocol](https://agentclientprotocol.com)
as children of its own orchestrator, in the background on this computer: the features 0.93.1 to 0.93.7 kept behind
the hidden developer setting `OCTOFLOW_APP_BACKEND`, which is gone. The app needs no herdr. Its agent tab shows each
agent's conversation, with its permission requests answered by a button; a run that stopped, failed or lost its
orchestrator has Resume; closing the window with runs running asks whether to keep them running or stop them, and
the top bar's "Settings…" sets what it does. The setup dialog checks each harness over the protocol and installs
claude's and codex's ACP adapters. The app does not run pi yet, and refuses opencode under `default` and
`acceptEdits`, where opencode would not ask before it runs a command; under `plan` and `bypassPermissions` it runs
in opencode's `plan` and `build` modes.

**Remote machines are the CLI's.** The project bar loses its machine field: a project saved with a machine opens on
this computer, and the app says once that `--machine` is a feature of octoflow's command line. serve takes no
`machine` parameter.

**Earlier app runs.** Runs an earlier app started in herdr stay herdr runs. The app lists and shows them, and their
agent tab shows the herdr pane when herdr can be reached here, else says to follow the run from the CLI; they
resume from the CLI (`octoflow resume`), not the app. The app no longer starts a herdr server of its own (the session
`octoflow`); one an earlier app started keeps running until you stop it with `herdr session stop octoflow`.

**The CLI is unchanged:** it runs its agents in herdr, as before.

**Rolling back.** An earlier release starts the app's runs in herdr again. It refuses the runs this one started
(`state.json` format 3), which stay resumable by any release that reads format 3.
