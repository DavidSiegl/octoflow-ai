## `close` deletes a run's local refs

- **Closing a run deletes the refs that kept its locked files.** A workflow with a locking step, such as `tdd`, keeps
  the commit of the files it locked under `refs/orchestrator/<key>/`, which only a run that ended `done` deleted, so
  a failed or stale run's commits were never collected by `git gc`. `close` now deletes them for every run it
  closes, failed, stale or finished, in place or `--worktree`, prints `deleted the refs under
  refs/orchestrator/<key>/`, and adds `refs deleted` to the run's `closed` line. A run without such refs, one in a
  directory that is not a git repository included, closes as before. If a ref cannot be deleted, or git refuses
  the repository of a run that locked files, `close` fails naming the prefix and records nothing, and a second
  `close` finishes.
- **`close` refuses a run saved as `done` whose orchestrator is still ending it**, as it refuses a running one: the
  orchestrator may be deleting those refs itself. One that stopped while ending closes as any finished run.
- Runs closed by an earlier release keep their refs: `git for-each-ref refs/orchestrator/` lists them, and
  `git update-ref -d <ref>` deletes one.
