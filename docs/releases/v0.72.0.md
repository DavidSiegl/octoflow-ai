## The run detail shows the run as an octopus

- **The desktop app's run detail** draws the run as an octopus in place of the row of stage chips. The head is the
  run, with its key and round: teal, coral once the run failed, and dimmed with closed eyes while it is stale. Its
  eyes follow the arm at work, or look at you while the run waits on you, and a bubble then asks for your answer or
  says the run is blocked.
- **Each stage is an arm**, left to right: the workflow's steps, the quality gate after each step it follows, and
  the pull request last when the run opens one. Every stage is there from the start, not only once the run reaches
  it. An octopus keeps eight arms, so a short workflow leaves the spare ones curled; a workflow of more than eight
  stages grows more. Each arm ends in a station with the step, who holds it (the role's label, "quality gate", or
  the pull request's number), and the harness and model of its last turn. A step run in several rounds shows `×2`,
  `×3`, and a verdict step shows its last verdict.
- **A verdict step's loop** is an arrow back to the step it sends the run to, solid once a verdict took it. A stage
  that ran before the loop back is marked as one to do again.
- **Below the map**, a line says what runs now and for how long, and the run's turns follow, newest first.
- The arms sway and pulses run along the working arm, unless the system asks for reduced motion; the map says
  everything at rest.
- **The runs overview's stage chips** also list the quality and publish stages from the start.
