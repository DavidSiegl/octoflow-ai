## Text read and quoted as Rust reads it

The orchestrator no longer imitates Python's string handling. What you may notice:

- **Quoting in messages.** A name, a path or a value an error quotes is in double quotes, `"../x" is not a name in
  the run directory`, where it was in single quotes.
- **Text that is not UTF-8** is named in Rust's words: `invalid utf-8 sequence of 1 bytes from index 12`.
- **Lines, blanks and digits.** A line of a review, a report, a spec or a quality file ends at `\n` or `\r\n` only,
  not at U+2028 or the other separators Python's `splitlines` knows; a blank is Unicode whitespace, which leaves out
  `\x1c`–`\x1f`; and a number, such as a finding's, is written in ASCII digits.
- **"Did you mean"** for an unknown key, step or prompt file names the closest known name by its number of
  single-letter edits.
