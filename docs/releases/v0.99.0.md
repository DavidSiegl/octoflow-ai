## `drain` runs a spec's tickets, one pull request each

A `ready-for-agent` spec with tickets under `issues/`, named `<NN>-<name>.md` or `<NN>.md`, is no longer run as a
whole. `drain` runs each of its `ready-for-agent` tickets instead, in number order, each as its own run ending in its
own pull request, and records it in the ticket's header as it does for a spec: `in-review` with its `Run:` and `PR:`
lines, then `resolved (PR #<n> merged)` once the pull request merges, or `ready-for-human`. A ticket waits for the
tickets on its `Blocked by:` line (`02`, or `<slug>/02` for another spec's) to be resolved, rather than building on
their open pull requests. The spec turns `done` once each of its tickets is `resolved` or `wontfix`. `--dry-run` lists
the tickets it would run. Drain starts a ticket only while its spec is `ready-for-agent`, but records the merge or
close of any ticket's pull request.

A ticket whose `Blocked by:` entry names no ticket, or more than one, or whose blocker is `wontfix`, is held for you:
drain runs the rest, prints `<ticket> needs the human: <why>` and exits `1`.

Drain now reads a `Status:` line by its first word, for specs too, so a note may follow it:
`ready-for-agent (reviewed)` counts as ready, where 0.98 left such a spec alone. Likewise `Blocked by: none (…)`
names no blocker. A spec without tickets drains as before otherwise.
