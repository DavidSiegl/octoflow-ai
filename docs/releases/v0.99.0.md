## `drain` runs a spec's tickets, one pull request each

A `ready-for-agent` spec with tickets under `issues/`, numbered `<NN>-<name>.md`, is no longer run as a whole. `drain`
runs each of its `ready-for-agent` tickets instead, in number order, each as its own run ending in its own pull
request, and records it in the ticket's header as it does for a spec: `in-review` with its `Run:` and `PR:` lines,
then `resolved (PR #<n> merged)` once the pull request merges, or `ready-for-human`. A ticket waits for the tickets on
its `Blocked by:` line (`02`, or `<slug>/02` for another spec's) to be resolved, rather than building on their open
pull requests. The spec turns `done` once each of its tickets is `resolved` or `wontfix`. `--dry-run` lists the
tickets it would run. A spec without tickets drains as before.
