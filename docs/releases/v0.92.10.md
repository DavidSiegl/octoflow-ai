## A run of a built-in workflow resumes with the steps it started with

A run of a workflow file saves the workflow's definition (its steps and their prompts) in its state.json, so that a
resume runs what the run started with. A run of a built-in workflow (`default`, `design`, `peer-review`,
`product-team`, `quick`) saved only the workflow's name, and a resume ran the built-in of that name in the octoflow
that resumed it: if a later release changed that built-in's steps or prompts, the run's saved phase, rounds and
verdicts no longer matched its steps. Every run now saves its definition, a built-in workflow's too, and a resume runs
it, whatever the resuming octoflow's built-in says. A run saved by an earlier octoflow, without a definition, resumes
on the built-in of its name in the octoflow that resumes it, as before, and saves that definition from then on; a run
that is already done keeps its record as it was, without one.
