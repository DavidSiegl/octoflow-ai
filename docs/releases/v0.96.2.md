## An approved run with nothing tracked to publish ends approved

A run whose Builder wrote its work only to files git ignores, such as a design draft under `.scratch/`, used to end
in an error at publish once the Reviewer approved it, and left the checkout on the run's unpushed branch. Such a run
now ends with its verdict, APPROVE or FINISHED, and opens no pull request: it checks the base branch out again (a
`--worktree` run keeps its worktree, detached), deletes its branch, and its summary and log say there was nothing to
publish. With the quality gate on, a Builder's first report of a round that changes nothing tracked goes to the
Reviewer without a quality round. A run that changed nothing while changes were still requested fails as before.
