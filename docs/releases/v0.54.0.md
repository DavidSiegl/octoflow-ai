## Run state in a format of its own

The orchestrator no longer writes its files the way the Python engine wrote them. What you may notice:

**Runs do not carry over.** A run that an earlier release started, finished or not, is not resumed by this one:
`orchestrator resume` refuses it with `run <id> was saved by an octoflow before 0.54.0; finish or close it with that
release, or remove .orchestrator/runs/<id>`, and exits 1. Finish such a run with the release that started it, or
close it, before you upgrade. `list` and `show` still list it, with that hint in place of its outcome, and `prune` and
`close` work on it as on any other run.

**`state.json` starts with `"format": 2`**, which says which shape it has. It and `metrics.json` stay one line of
JSON, now without blanks after `:` and `,`, so the release that started an old run still reads a project where this
one has saved runs too.

**Times** are read only with their offset (`Z` or `+02:00`), as every harness, gh and PyPI write them: a time
without one, or with hour 24, is no longer read in the machine's zone. Times the orchestrator writes are unchanged,
such as `2026-11-03T08:34:31+00:00`.

**serve's JSON** answers and events are compact, without blanks after `:` and `,`; their keys and values are the same.
