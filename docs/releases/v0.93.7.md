## codex runs over ACP in the desktop app (behind the developer switch)

With the developer switch on, the app's runs start codex's agents over ACP, through its adapter
(`@agentclientprotocol/codex-acp` 2.5.0, which brings its own codex). The setup dialog offers "Install codex's ACP
adapter (about 649 MB)" beside claude's: a Node of its own and the adapter, pinned and verified as claude's are, in
octoflow's data directory under `codex-acp`. The run's permission mode becomes a codex mode: `default` and `plan` run
read-only, `acceptEdits` may edit the workspace, `bypassPermissions` runs with full access. The setup check of codex
also needs a codex login (`~/.codex/auth.json`; an API key alone is not enough) and says how to log in. The
adapter runs its own codex: a `CODEX_PATH` in the environment does not reach it.

serve's `POST /setup/claude` is now `POST /setup/adapter?agent=claude` (or `codex`), and `/setup` answers `adapters`,
one `{"agent", "installed", "megabytes"}` each, in place of `claude_install`. Runs in herdr are unchanged.
