## Runs over ACP start detached and listen on a socket (behind the developer switch)

With `OCTOFLOW_APP_BACKEND=acp` in serve's environment, a hidden developer setting, the desktop app's new runs no
longer open in herdr. serve starts `octoflow run … --acp` detached from itself, so the run outlives the app, with
its output in `run.log` in the run directory; under an AppImage it runs the AppImage file, whose mount does not end
with the app. A run that exits before it saves its state is reported with the log's last lines.

Such a run drives its agents over ACP as its own children, each in a process group recorded in the run directory;
a resume ends a group that an orchestrator killed before it left running, and on Linux an agent dies with its
orchestrator. Each role's agents' sessions, prompts, updates, permissions and answers go to
`<role>.events.jsonl`, and the run listens on a Unix socket (named in the run directory's `socket` file) by which
the app will answer permissions and stop the run.

Without the setting nothing changes: the app starts runs in herdr as before. `run --help` does not offer `--acp`.
