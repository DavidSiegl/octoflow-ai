## Two forgets of one project no longer run at once

`octoflow forget` and the desktop app's forget could run over one project at once from separate processes (two
apps, or the app and the command line), and both delete the same run and archive its metrics twice. Every forget
that deletes now holds a lock file, `.octoflow-ai/forget.lock`, while it works, and another forget of the project
is refused, naming the process that holds it; within one app, a second forget still waits for the first. The holder
renews the lock before each run it forgets, so a lock its holder left when it died is taken over once it has gone
ten minutes without renewal, or a minute when it names a process of this machine that is gone. A dry run takes no
lock.
