## A run in a project without ci/gate.pin keeps one gate release

A project whose base has no `ci/gate.pin` (every project `doctor --setup-gate` sets up since 0.91.0, unless
`--pin-gate` asks for one) is judged by the octoflow-gate release built into octoflow. Until now each quality round
took the release built into the octoflow running that round, so a run started under one octoflow and resumed under a
newer one with another built-in release was judged by two releases, and its rounds' failures were compared across
them. A run now saves the built-in release in its state.json when its first quality round starts, and every later
round, after a resume under another octoflow too, is judged by that release. A run whose base has `ci/gate.pin` is
judged by that pin, as before. A run saved by an earlier octoflow, without this field, takes the release of the
octoflow that resumes it at its next quality round and keeps it from then on.
