## A proof the Builder moves into the project is no longer held against it

- **A proof whose file is gone from its proofs directory is taken as moved into the project.** The proof step's
  note lets the Builder move a proof into the project as a regression test. The orchestrator then found the file
  gone, recorded that the proof did not run, and went on carrying it as erroring: the Builder heard in every later
  round that it did not pass, and the verdict step that it "no longer fails but errors", even when the moved test
  passed in the project. Now the round that finds it gone tells the verdict step once that it was not run, as it
  is taken as moved into the project, and asks it to check that the change holds it as a test that passes, or else
  to let the proof's finding stand; the Builder is not told of it, and later rounds do not rerun or name it. A proof that still exists and errors is carried and told as erroring, as before.
- A run's `state.json` records such a proof with `"moved": true`. A run saved by an earlier release has no such
  field and reads as before, and an earlier release reading one that has it ignores the field.
