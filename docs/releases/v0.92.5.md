## A run resumed under another herdr server no longer leaves its old workspace open

A run started in the desktop app and resumed from a shell (or the other way round) talks to a different herdr server
than the one it started in. Until now the resume looked for the run's workspace in the new server, did not find it,
and opened a new one there, leaving the old workspace open in the first server; and if the new server happened to
have a workspace with the same id, the resume took that one for the run's. A resume now looks the workspace up in the
server the run saved: if it is still open there, it is closed and a new one is opened in the server the resume
reaches, which the run records from then on. A server reached under two names, or through `--machine`, still counts
as the same one, so such a resume keeps its workspace.
