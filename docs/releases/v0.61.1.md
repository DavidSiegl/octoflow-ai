## The quality gate comes from an octoflow-gate release

- **Jenkins judges this repository's changes with a released gate.** The Gate stage downloads the
  [octoflow-gate](https://github.com/DavidSiegl/octoflow-gate) release that `ci/gate.pin` names, v0.5.0, checks it
  against the pinned sha256, and runs it, rather than the `gate.py` in this tree. A quality build takes the pin, the
  rules and the new `gate.toml` from the `main` commit it judges by, as it took `gate.py` before. A release that cannot
  be downloaded, or does not match, fails the build as one the gate could not judge.
- **Builds archive `quality.json` beside `quality.md`.** It is the release's machine-readable report; nothing reads it
  yet.
- **`judged-in-quality` compares the files that now decide the judging.** A quality build is trusted for a pull
  request only when `ci/gate.pin`, `ci/fetch-gate.sh` and `gate.toml` are the same at the `main` commit it was judged
  by, along with the rules and toolchain files as before; `gate.py` and `ci/gate-rust/` no longer count, since no
  build judges with them.
