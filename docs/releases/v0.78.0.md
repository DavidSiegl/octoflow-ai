## serve reads, checks, saves and deletes a workflow

The groundwork for the desktop app's workflow editor: serve answers four new endpoints, which reach no project, since
workflows are this machine's.

- **`GET /workflow?name=NAME`** gives one workflow to edit: its definition, whether it is built in, and its file's
  path and text, with whether that text is hand written (not the canonical form a save writes).
- **`POST /workflow/check`** names a definition's first problem under a name, and the placeholders its prompts may use,
  listed even while a prompt is wrong.
- **`POST /workflow/save`** writes a definition in canonical form to `workflows/NAME.toml`, through a temporary file
  and a rename, but only if the file is still the text the editor opened: a file changed since gets 409.
- **`POST /workflow/delete`** removes a workflow's file under the same rule. Built-in workflows have no file to delete.
