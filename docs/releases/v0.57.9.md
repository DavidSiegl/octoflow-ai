## A run waits out a short outage of origin

- **A fetch that cannot reach `origin` is tried again.** When git says it could not reach `origin`, or that `origin`
  would not let it in (as GitHub refused known SSH keys during its incident of 2026-11-04), the run tries three more
  times, 5, 20 and 60 s apart, and logs each wait as `origin unreachable, trying again in 20 s (2 of 3)`. This covers
  every fetch of a run (the fast-forwards before the interview and before branching, a worktree run's checkout, the
  merge before publishing), the listing of the quality gate's refs on `origin`, and `prune`'s read of each run's
  branch there.
- **An answer that will not change is not waited for:** a branch `origin` lacks, a repository not found, access
  denied, or an HTTP 403 or 404 stops the run at once, as before.
- **When every try fails,** the error keeps git's message and adds `(origin still unreachable after 4 tries; check
  that it can be reached: …)`, naming githubstatus.com when git's message names github.com, and
  `ssh -T git@github.com` too when it was over SSH.
  Resume the run once `origin` answers.
- A Ctrl-C during a wait stops the run as interrupted, without the remaining tries.
- `prune`, and the sweep a run makes before it starts, stop at the first run whose branch `origin` stays unreachable
  for, rather than waiting for every run in turn.

Not retried: a git command that hangs until it is killed at its 300 s limit, and writes to `origin` (pushes, branch
deletions, `gh`), which stop the run at the first failure as before.
