## The local gate runs octoflow-gate 0.7.0

- **`--quality-gate local` runs the gate as one program.** octoflow-gate 0.7.0 ships `gate`, its port to Rust, in
  place of `gate.py` and its Rust helper; the orchestrator runs `gate --base <base> --config <the base's gate.toml>`
  in the checkout. The gate takes the linters' rules from the `pyproject.toml` beside that `gate.toml`, so a change
  still cannot loosen how it is judged. docs/quality-gate.md, "The local gate", has the details.
- **The machine needs Linux on x86_64, `setsid` and an `env` that takes `--default-signal`, and no longer
  `python3`.** The preflight checks them before the interview. A project with Python tests still needs the Python
  they run in on `PATH` (`python3`, or `gate.toml`'s `python`), as it needs its other test tools and linters.
- **A base whose `ci/gate.pin` names a release before 0.7.0 stops the run with an error** that says so, before any
  download: those releases ship no `gate`. Raise the project's pin to 0.7.0 first.
- **A base without `ci/gate.pin` is judged by octoflow-gate 0.7.0**, where 0.5.0 judged it before. A base without
  `pyproject.toml` is judged by the linters' own defaults, where an empty `pyproject.toml` stood in for it before.
- **This repository's quality builds use octoflow-gate 0.7.0 too.** Its pin can be lowered to roll back only as far
  as 0.7.0; below that, revert this release's cutover, whose Gate stage runs a release's `gate`.
