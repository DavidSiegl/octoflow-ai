## doctor sets a project up for the local quality gate

- **`doctor` checks what `--quality-gate local` needs.** Every `doctor`, and so the desktop app's setup dialog, now
  shows an optional check, `local quality gate`: python3 3.11 or later, curl, tar, sha256sum or shasum, a `ps` that
  takes `-ww`, and a writable gate cache, where the agents run. It is the check a run with `--quality-gate local`
  makes before its interview, so a machine that fails it can still run without the gate. Making the check creates
  the gate's cache directory, `${XDG_CACHE_HOME:-~/.cache}/octoflow/gate`, as a gated run does.
- **`doctor --setup-gate` writes the gate's files into the project.** After the checks, it writes at the top level
  of the project's checkout, where the agents run, whichever is missing of `ci/gate.pin`, naming the gate release
  this engine was tested with, and a starter `gate.toml` whose `[[test]]` commands are guessed from the project's
  kind (Cargo, Python, npm, Go), or left for you to add when it recognises none. A file already there is kept, and
  doctor says so. Nothing is committed: the gate reads these from a run's base commit, so commit them, after
  checking the guessed commands. Runs stay ungated unless given `--quality-gate local`. Without the flag, `doctor`
  writes nothing into the project.
- **The setup dialog has a "Set up the quality gate" button**, which does the same through serve's new
  `POST /setup/gate` and shows which files it wrote and which it kept.
