## The desktop app starts runs

The desktop app no longer only watches runs: "New run…" above the runs overview opens a form for a new run in the
open project.

- **The form** asks for the task, the workflow (`default` unless you pick another, its description shown; one whose
  file does not load cannot be picked), an agent and a model for the whole run (the workflow's own unless you pick
  them), and two boxes: "No pull request", off as on the CLI, and "Separate worktree", on, so that runs started side
  by side do not share the checkout.
- **Start** runs `orchestrator run` with them in a new workspace of the herdr server on this computer, through
  serve's `POST /run`, where it can be watched and interrupted as a run started by hand. It needs that herdr server
  running, also for a project on a machine, whose agents then run there.
- **Afterwards** the app opens the run once its overview lists it, saying so while it waits; "Stop waiting" goes
  back to the overview. A run that fails before it saves its state, such as one the checkout already holds without
  a worktree, leaves its error and the last lines of its pane in the form, with what you entered.
