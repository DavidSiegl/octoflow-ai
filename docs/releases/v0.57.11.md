## The new-dependencies check judges every source a package is named with

- **A crate named from several sources is a dependency from each.** `foo = "1"` in `[dependencies]` and
  `foo = { git = "…" }` under `[target.'cfg(windows)'.dependencies]` used to count as foo from crates.io only, so the
  repository was never seen. Now each source of a new crate is judged on its own: a crate the spec does not name gets a
  `not-in-spec` finding for each of its sources, and one the spec names an `added` (or `other-index`) finding for each.
  What crates.io says of foo (unknown, young) is said only of foo from crates.io, never of its other sources. A source
  the change adds to a crate the project already had, alongside its old one, is `source-changed`, naming the sources
  at the base and in the change. A `Cargo.lock` that lists a crate from several sources is read the same way.
- **The same holds for Python packages.** A requirement with a URL beside one of the same package without, each entry
  of a `[tool.uv.sources]` list (each for some platforms), and each registry `uv.lock` has a package from is a
  dependency from that source. Before, a package kept one source: the last requirement's, the first entry of a
  sources list, and the last registry in `uv.lock`.
- **`pulled-in` lists a package once for each source** the lock file has it from.
- **`workspace` that is not `true` makes a Cargo manifest unreadable.** An entry with `workspace = "true"`, `1` or
  `false`, which Cargo refuses, was read as a crate from crates.io; it is now an `unreadable` finding naming the crate,
  its table and the value.
