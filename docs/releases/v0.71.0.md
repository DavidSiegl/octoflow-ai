## The Jenkins quality gate is gone: the local gate is the only one

This release breaks a flag and a command; a run saved by an earlier release still resumes.

- **`--quality-gate` takes only `local`.** Any other value, which named a Jenkins quality job, is a usage error
  (exit status 2): "the Jenkins quality gate was removed in 0.71.0; use --quality-gate local". The local gate judges
  each quality round on the machine the run is on, by the base's `gate.toml` and `ci/gate.pin`, as `--quality-gate
  local` did before.
- **`orchestrator judged-in-quality` is gone**, with the Jenkins client behind it. No quality build exists for it to
  find.
- **A run started on a Jenkins quality job** resumes on the local gate, warning "the Jenkins quality gate was removed
  in 0.71.0, so the local gate replaces job …". Past its first round, the resume first checks the machine as
  `resume --quality-gate` does (gitleaks, and what the local gate needs to fetch and run octoflow-gate), unless it
  turns the gate off. A quality round that was in flight on Jenkins starts again on the local gate. `show` names the
  local gate for such a run before its resume, with the Jenkins job it replaces.
- **`orchestrator-ci/*` branches** are no longer pushed, and the orchestrator leaves any an earlier release pushed on
  origin; delete them by hand with `git push origin --delete`.

## Turning the gate off on resume stops the local gate's job

- **`resume --no-quality-gate`** on a run killed while the local gate judged a quality round now stops that round's
  job, which went on running the project's tests unattended, and clears its directory (its git worktree of the
  snapshot, the gate release it downloaded). A failure to is logged and the run goes on at `review`, as before.

## The Jenkinsfile builds only branches and pull requests

Nothing a user runs changes. The `GIT_REF` parameter, through which a Jenkins quality job built an orchestrator
snapshot, is gone, and every build judges by the gate and rules in its own tree.
