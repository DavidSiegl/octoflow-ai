## No false startup alert for an agent that already did its turn

When you answer an agent in its pane before octoflow sent it its prompt, and the agent writes its handoff file from
that, octoflow now records that the agent is past its startup. A later block of that agent is asked about as a
question needing your answer, not as a startup dialog it waits on before it starts. An agent restarted this way is no
longer announced as "restarted; the interview starts over" in a later turn, and it still gets the full prompt a fresh
agent needs. An agent that is really stuck at its startup dialog is still told so, with the hint about the folder-trust
prompt.
