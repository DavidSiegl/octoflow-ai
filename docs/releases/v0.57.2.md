## A run that stops while it ends is finished by `resume`

- **`resume` finishes the ending of a `done` run that stopped part way through it.** A crash, a SIGKILL or a lost
  machine after a run was saved as `done` used to leave it without `summary.md` or `metrics.json`, with its turns'
  tokens uncounted, still owned, the human never told it finished and a published run's herdr workspace open, and
  `resume` returned its verdict without doing any of it. Now a run its orchestrator had not released yet is taken
  over and ended again: tokens counted where they are not, both files written, the run released, the "Run finished"
  notice given and the workspace closed. A released run that lacks a file gets that file written and nothing else.
  A run whose ending is whole is still left as it is, not even saved.
- **A run's ending writes its files before it releases the run.** So a released run is one whose files were written,
  and the human is told once, after the release. A Ctrl-C during the ending now leaves the run owned, and `resume`
  finishes it.
- **`resume` refuses a `done` run that may still be ending.** While its orchestrator holds it with a fresh
  heartbeat it looks alive and needs `--force`, as an unfinished run does. `resume` applies none of its flags to a
  `done` run: its record keeps the settings it ran with.
