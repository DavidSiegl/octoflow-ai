## serve drops a stopped HTTP server before it starts another

Nothing the orchestrator or the desktop app does changes. When serve's HTTP server stops accepting connections, serve
starts another on the same port, and it now drops the stopped one first, not after the new one is accepting. The order
only mattered to a test that simulated a stopped server by unblocking it, which left its accept thread running; that
test failed about one run in ten because of it.
