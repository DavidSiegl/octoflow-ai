## The engine sees new files and moved submodules whatever the user's git config says

- **A run whose Builder only adds files now commits them.** The engine decided whether to commit by asking
  `git status --porcelain`, which lists no new file with `status.showUntrackedFiles = no` in the user's git config. The
  status then read empty, the engine skipped the commit, and the new files never reached the pull request. It now lists
  every new file, also those in a new directory, one by one.
- **The same holds for a Builder that only moves a submodule to another commit.** With `diff.ignoreSubmodules = all` or
  `submodule.<name>.ignore = all`, that change read as nothing; it is now listed.
- **A new file of yours already in the checkout is refused.** The check that the working tree is clean, made when a run
  starts and again after the interview, missed untracked files under that setting, so they went into the commit with the
  Builder's change. It now refuses them.
- **`close` lists every file it discards.** The list of the files that go with a failed run's worktree left out the new
  ones under that setting, and printed a name that is not ASCII in quotes and octal escapes; it now shows every file,
  by its name.
