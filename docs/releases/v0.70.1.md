## A herdr server that does not come up says why

- **The herdr server the orchestrator starts** (the session `octoflow`, when no server is running) writes its output
  to `${XDG_STATE_HOME:-~/.local/state}/octoflow/herdr-server.log` instead of discarding it. A server that is not
  running 15 seconds after the start, such as one that exits at once over a bad `config.toml`, fails the run's start
  with that file's last lines, or with the file's name when it is empty or cannot be read; until now the error said
  only that the server was not running.

## A run the app started says which herdr session shows it

- **POST /run's 201 and 202 answers** add `herdr_session` when the run's workspace is in a named herdr session
  that serve started for it: `octoflow`, when no herdr server was running. Without it, the workspace is in the
  herdr server serve's own environment reaches, as before.
- **The desktop app's "not listed yet" hint** then says `herdr session attach octoflow` shows why a run never
  appears, instead of pointing at a herdr workspace that a user with no herdr open has no way to see.

## Setup fixes that read right in the desktop app

- **`orchestrator doctor` and the app's setup dialog** word two fixes by what to choose rather than only by a flag:
  a project that is no git checkout says "choose a git checkout as the project (--cwd), or make one with git clone
  or git init", and a check made outside a herdr pane says "run from a herdr pane, or choose a herdr machine
  (--machine)". The app's dialog, which shows the same checks, no longer asks to pass a flag the app has no place
  for.

## A conflicted spec whose pull request merged is marked done after `refresh`

- **`orchestrator refresh`** on a run whose pull request was merged or closed meanwhile now records that it cleared
  the conflict, as it already did for an open one. The next `drain` then settles the run's `ready-for-human` spec by
  the pull request: `done` for a merged one, `ready-for-human` for a closed one. Until now such a spec stayed
  `ready-for-human` for good, unless `drain`'s own refresh had found the pull request first.

## The tests' scratch directories come from the tempfile crate

Nothing a user runs or saves changes. The engine's, the app's and xtask's tests, and xtask's eval and bundle chores,
make their temporary directories with the `tempfile` crate in place of four hand-written copies, each named its own
way.

- **One way to make a scratch directory**: a unique name and its removal on drop are the crate's, so a fix to either
  is made once.
- **An eval trial kept by `--keep` or a Ctrl-C** stays where it is reported, as before.
