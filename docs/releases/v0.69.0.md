## Commands leave a run an earlier release saved to that release

- **`close`, `prune`, `refresh` and `drain` no longer act on a run whose `state.json` this release cannot read**:
  one saved by a release before the current state format, or one whose fields do not read. They say why: finish
  or close it with the release that saved it. Before, `close`, `prune` and `refresh` acted on such a run by the keys
  they found in it. `prune` and `refresh` skip it; `refresh` then exits with 5, as when a pull request still
  conflicts, since its conflict is not known to clear. `close`, and `refresh` given that run by name, fail with those
  words. `drain` stops at a ready spec whose run is such a one: for a finished run, set the spec's `Status:` and `PR:`
  lines by hand, or drain with that release. `list` and `show` still show it, with why.
- **A `state.json` that is not an object naming its run** (`run_id`) is refused as corrupt, as one that is not JSON
  is.
- **A run saved as `done` whose orchestrator is still ending it counts as running everywhere.** `prune` no longer
  deletes its branch, `list` shows it as `running`, and a run that starts or resumes in its checkout stops, as beside
  any running run. One whose orchestrator died while ending it is `stale` in `list`, with its `resume` command.
