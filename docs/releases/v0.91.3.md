## A failed run's summary reaches the desktop app however long it took

When a run fails, octoflow writes its `summary.md` after the save that records the failure. On a `--machine` run that
reads the round results over SSH first, which could take longer than the minute the desktop app's event stream keeps
listing a finished run's files, so the summary never showed up there. The failing run now saves its `state.json` once
more after the summary, unless another orchestrator took the run over in the meantime, and the event stream lists a
finished run's files again whenever its `state.json` is written.
